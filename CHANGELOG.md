# Changelog

Changes in each public release of SpecBoard that people using it can see (newest first).

## 0.3.62

- Local agent: a switch in This Mac's settings runs the agent bundled with the app for your user on this Mac, with no SSH and no other host. While it is on, the agent keeps this Mac's projects and receives MCP on this Mac's 127.0.0.1, so AI sessions on this Mac can read and write them with an access key, and This Mac's settings get the Hub, Access keys and Public tabs. Turning it off moves the projects back into the app's own store. Moving a project between This Mac and its agent keeps the folders its working directories and exports are bound to.
- Hub: your own agents can share projects with one another. "Add hub" under the list of places puts a hub on a host reached over SSH; each agent joins or leaves from its Hub tab, and "Share…" shares a project with another agent to read, or to read and write. A shared project is listed in the other agent's access-key permissions with its owner's name, and sessions with a permitted key use it with the same tools (no copy is kept; the owner's agent answers). `project_list` lists shared projects with `owner` and `access`; calls that touch folders on the owner's host are refused over the hub.
- Faster MCP and window: while nothing is written, a project's tree is read once and used again (on a 3,000-card project `card_read` went from 53 ms to 5 ms and `branch_list` from about a second to under 1 ms). The agent takes a new connection's call at once and no longer counts every card to find a project. `export_execute` neither waits behind other writes nor holds them up, and a window connected to an agent stays responsive while a large project loads.
- Smaller history: a long document changed a little no longer puts the whole document into the history each time, only what changed (a 266 KB document edited 20 times took 5.3 MB of history; now 0.4 MB). Going back, undoing one commit and reading a commit's contents work as before. The history's size, and what a cut would free, count the same content once.
- Section maps with many lines: after a card is put somewhere, only the lines near it are routed again and the others stay exactly where they were (on a map with 1,000 lines, about a dozen are searched instead of all of them). Opening the window again routes every line afresh, so a line may run a little differently from right after the move.
- Linux agent: it lets go of memory after reading a project (a large project, idle, went from 1.9 GB to about 140 MB). Only the two most recent copies of a store taken before an upgrade are kept.
- Export: a new format writes cards' lines into one JSON file (JSON Connections, `format: json-connections`), narrowed by `kinds` and the new `lines`. In the Export tab the formats have the same names everywhere (TypeScript, Zod, JSON Schema, JSON Data, JSON Connections), and pressing a row shows its settings in the property panel, where `to`, `format`, `kinds` and `lines` can be changed in place. MCP: `export_update` takes `change` to alter one row in place, `export_read` says which rows write each file, an export holds one row per `from` and `to`, and a row whose `from` is gone can be removed.
- Editing: pressing the selected Edit switch again no longer discards what was being typed. Shapes, notes, images, cards, fields and sections added in the window can be undone with ⌘Z. Delete on the selected cards asks, deletes them at once, and ⌘Z brings them back at once. A refusal when creating a section, a name or a card is said in red under the field, without closing the window.
- Navigator: "＋" sits beside the search field and adds a card or a section to the open section, or a working directory from anywhere (read as git when the folder has a .git). A goal whose work branch was merged offers "Continue (new branch)". Specs can be added in a document section.
- Merge: an enumeration value, a document row, a version or a Scenario renamed on a branch merges as the same thing renamed (it used to merge as removed and added), and the diff says so. Rule names follow a renamed field through embedded shapes.
- Documents and maps: an embedded section diagram draws cards without lines too, and says why when it has nothing to draw. Working-directory maps no longer put small files' boxes on top of each other.
- Project settings: the explanation at the top of each tab is behind an ⓘ beside the title.
- MCP: the type `url` accepts custom schemes such as `com.example.app:/cb` and `urn:…`; `card_list` `query` searches Scenario steps; a top-level key written inside `value` is refused with a message that says so.
- Projects are saved in a newer format (history), and older versions of the app and its agents cannot open them. The first launch repacks the history there is, once, after keeping a copy beside the store (seconds to tens of seconds for a large history; the first connection to an agent may fail once — connect again). Update the app and its agents together, and reconnect AI sessions to MCP.
- Hardening from the security review before this release: a call to a shared project gives up after five minutes when its owner stays linked but does not answer, and says it is not known whether the call arrived (a read is not sent again), instead of holding the connection for good; the local agent starts when the path of its home has an equals sign in it; moving a project between stores refuses data whose history rows name another project's commits or branches; a malformed history row is refused before a very large text is built from it.

## 0.3.53

- Whiteboards: a new kind of section for explaining a design in pictures. Place shapes (rectangle, rounded, ellipse, diamond, cylinder, text only), sticky notes, SVG and images from the map band, join them with arrows that carry their own label, dashing, ends and color, and write in a shape or a note in place (Return keeps it, Shift+Return adds a line). Images can be chosen, pasted or dropped from Finder. An arrow's label that does not fit between the shapes wraps to two lines. MCP writes them as `kind: sketch` and `kind: image` cards and `arrow` lines, places shapes left to right along the arrows when no position is given, and reads a whiteboard as text in `as: diagram` and an image itself in `as: image`.
- Specs: a new built-in kind for a feature's story (As, I want, So that) and its Scenarios (Given, When, Then, And, But), written in place in the card editor. Each Scenario can be linked to the tests that check it with the new `testedBy` line (to test cards, rows, or test functions in a working directory); the map and the document view show how many tests each has, and the inspection lists Scenarios with none. Specs export as Markdown, and a formatted document can be turned into a spec.
- Map tabs: right-click a map tab for New Tab or Duplicate Tab, or right-click a section in the navigator for Open in New Tab. Each map tab keeps its own view, zoom, line switches and filters; a section picked in the navigator, a link or app_control goes to the map tab in front.
- Merge: after the merge window merges a branch into main, a notice says which goal still has it as its work branch, with Finish goal. Merging one branch into another no longer quietly undoes changes made on main in between. MCP merges say the destination as `into` and take `source` or `into` per conflict, and show changed text as changed lines.
- Undo: ⌘Z and ⌘⇧Z undo and redo what was edited in the window. Going back in a branch's history also restores the main it was made from.
- Flow cards: the way to the node below is an arrow between the rows, and jumps are dashed arrows in a narrow strip on the left (grey for otherwise, orange for timeout, red for failure). A decision's new branch asks for its destination first.
- Section maps: a chip says how many value objects and enums are folded inside other cards and lists them with the fields that hold them; another says when cards overlap and tidies them. Group frames grow to hold the cards inside them. Lines keep cards where they were placed when switched.
- Navigator: drag tasks and goals into a goal, or right-click a card on a board map to put it into one. Search with `diff:` (and `diff:made`, `diff:changed`, `diff:removed`, `diff:main`) to see what a branch changed.
- Project list: All Projects at the top lists the projects of every place, grouped by place.
- Tabs: press × several times in a row to close tabs one after another without moving the pointer. ⌘+, ⌘− , ⌘0 and ⌘9 zoom the map; ⌥⌘+, ⌥⌘− and ⌥⌘0 change the text size.
- Card editor: a refused field, value or tag is said in red under the field. The header's line count matches the property panel.
- Settings: the sidebar looks like the navigator; buttons, pull-downs and bars are made consistent across the window.
- Language: with the app in English, kanji and kana are still drawn in Japanese forms when the Mac prefers Japanese.
- MCP: `card_read` `as: impact` lists every path a deletion would break, including table columns through embedded shapes; reading fields with `used_by` and `ref_by` gives the flows and lines they reach. Sections, project settings and kinds have a `rev` that refuses a write over a newer change. `card_list` with `include: []` returns only path, kind and label, and refuses unknown tags and fields. Writing a second tag of an exclusive group warns. Lines can be changed in place, and versions of a stacked document moved. Diagrams name lines by their kind.
- Export: formatted documents get anchors for their items, so links land on the item. JSON Schema and Zod accept the same values as the examples check for alternative types, embedded shapes and constants.
- Agent: one app that stops reading notifications no longer holds up writes from other sessions; health checks and SSH errors no longer stall.
- Whiteboard images: an interlaced or 16-bit PNG or a GIF, which is decoded whole to be shown, may be up to 4096 pixels a side (larger ones took gigabytes of memory to draw); images in a project file are read even when their base64 is wrapped. MCP cannot write an image card's picture fields by hand when changing a card into an image.
- Fixes: inspection rules follow renamed fields; the line beside a file's line numbers no longer runs up over the tab bar and header; a branch diff lists changes to enumeration values again; sequence diagrams with long step names, actor groups named after a color, or labels starting with a backquote are drawn correctly; edits made in the window no longer drop lines, versions or keys an AI added at the same time; links to a project that cannot be opened say why instead of opening the wrong one; importing a project file never writes into another project.
- Projects are saved in a newer format (images), and older versions of the app cannot open them. Update the app and its agents together, and reconnect AI sessions to MCP to get the new tools.

## 0.3.29

- Actors: a new kind of section for something that provides and uses things (a system, a person, or something external). It holds the flows it carries out and the actors inside it, and opens as a Map or a Sequence of the flows others use. Any section can have its own icon and color, shown in the navigator, tabs and section ghosts.
- Sequence diagrams: lifelines are only the ones that act, seen from the flow's depth; open an actor to see the ones inside, or fold them into their parent. Steps are named bands, and calls to the same actor's flows show their contents in nested frames. A start with no caller written, or a write with no store written, is drawn as an orange dashed gap instead of being guessed; a start can take calls from anyone (MCP `anyCaller`). The heads stay pinned at the top when you scroll. Branches and loops become alt and loop frames, and a diagram too large to draw says so instead of hanging the agent.
- Inspection: finds partners written as text that name a flow or an actor, and stores that are not written (with the candidate stores when more than one is reachable).
- Groups: named frames on section maps and goal maps, with a corner, color and fill of their own. Moving a group moves the cards inside it. MCP reads and writes them as `groups`.
- Arrange: a button on the map tidies overlaps, or arranges cards along their lines (referenced cards to the left, callers to the right, groups as one block). The result is the same each time and does not freeze the screen. MCP `section_update` has `tidy` and `arrange`.
- Data cards: a shape can give a list face, so each element of an array is one row with a mark, a note and contents that open. MCP names array elements by their primary key and can add or delete one. Merge compares data cards field by field and element by element.
- Kinds: project settings edit kinds with a form as well as JSON, with a live preview of a card of that kind. Built-in kinds open in the same form, read-only.
- Built-in kinds: line names now say the same thing as their labels (`notes` → `rules`, `of` → `shapeOf`, `branch` → `condition`, `event` → `awaits`, `peer` → `partner`), and every line that can appear in the same diagram looks different. The screen takes the words for sections, card badges, fields, lines and flow exits from the kind definitions. Goal status and priority are stored in English and shown in the app's language. Existing projects move to the new names when they are opened.
- Goal cards show their status in the head only, and other fields as rows only when they are written. Completed and cancelled sections have their own icons.
- Notes are Markdown and are drawn as Markdown on the map.
- Enumerations: "open" (not exhaustive) can be switched in the property panel. Sections of fields the screen cannot write say they are written over MCP.
- Mention lines (references from a body to other cards) are hidden at first and can be turned on from the line toggles; MCP diagrams include them only when asked.
- Formatted documents: right-click a row to copy its path or a `[[…]]` link. Brackets in the margin show the nesting of items.
- Cards with a fixed height keep a half-row strip above and below their rows for the "more" counts, and opening a row in such a card scrolls it into view.
- Navigator: parent rows stay at the top while you scroll, sections list cards, ghosts and then child sections, the change dot on an open row is only for that row itself, and large trees no longer rebuild on every selection.
- Maps with many lines stay fast when you drag cards, click, or come back to a section seen before.
- Updates: choose whether new versions download automatically (off by default), turn periodic checks on or off per source, and find new versions in notifications instead of a window. "Update Now" checks again and takes a newer version if there is one.
- Language: places that showed Japanese with the app in English now follow the app's language, including the menu bar and open and save panels.
- MCP: `kind_list` says what each kind is for (`purpose`) and which kinds only the core creates (`systemOnly`); answers leave out empty and repeated values; partial table cell edits answer with only the rows changed; ghosts can be created with a position; the whole-card key for merge conflicts is `(whole)`.
- Security: unknown or revoked access keys are refused with 401 before the request body is read; the agent has time limits for slow connections; a project name or slug that clashes with one the key cannot see is refused without naming it; update sources read from settings are checked again, and a Forgejo token is only sent over https.
- Fixes: a crash when a picture over MCP was asked for an area far past the map (now refused beyond ±1,000,000 cells); a crash when opening a section whose groups, read from a project file, were too large (they are now brought within range); a crash when the SSH connection to an agent host was lost; a crash when opening a section while a font could not be loaded; Swift files with `"#` inside raw strings losing their functions and highlighting; moving or resizing a card on a branch losing its size; diagrams that used up the agent's memory on densely linked projects.
- Projects are saved in a newer format, and older versions of the app cannot open them. Update the app and its agents together, and reconnect AI sessions to MCP to get the new tools.

## 0.3.2

- Update sources: when you have not chosen one (or the one you chose was removed), the app uses the first source you added, and this repository's releases only when you have added none. Adding a source no longer changes the one in use.

## 0.3.0

The first public release of SpecBoard.

- A project is a board of cards: entities, enums and value objects with their fields, lines between cards, flows that describe how a system behaves, documents (formatted, free, stacked), tables, data, and SVG or HTML cards, in sections with tags.
- Branches and merge requests: plan a change on a branch, review the difference, and merge it into main. History, undo, and an inspection that finds broken paths and mismatches.
- A board of goals and tasks to plan the work, linked to the spec.
- Tabs for what you open: the section's map first, then cards, Connections maps and settings, remembered per project.
- MCP for AI agents through `specboard-agent`, installed by the app on macOS (Apple silicon) and Linux (x86_64) hosts over SSH. Access keys choose which projects an agent may read or write.
- Exports to TypeScript, Zod, JSON Schema, Mermaid and Markdown, into the folder given at each export.
- Working directories: link a folder and read its code (21 languages) next to the design.
- English and Japanese.
- Signed with Developer ID and notarized; updates come from this repository's GitHub Releases.
